# project-eval(本地项目评估 skill)

评的不是「代码写得好不好」,是「项目能不能让一个不了解它的 AI 自己跑起来」:
文档与工程设施是否把上下文交代清楚、有没有可执行的验证、雷有没有被摊开。

## 安装

- **用户级安装**:`mkdir -p ~/.claude/skills/project-eval`,把包内全部文件拷入该目录
  (重启 Claude Code 生效);特殊需要装项目内亦可,**安装位置不影响评估行为**。
- **零依赖,不要求安装任何包**:Python 3.9+(仅标准库),`python3` 可用即可。
- 评估器自带排除集双保险:无论装在哪,评估器自身文件都不会被自己拾取计分
  (安装位置在排除集内的「自拾取事故」必须为零)。

## 铁律(评估器对被评项目)

**只读、不跑、不改**:不执行被评项目代码、不装依赖、不起服务、
不写被评项目任何文件;报告与产物只落在被评项目之外。

## 使用(统一入口)

```bash
# 位置参数指向「目录」= 项目评估;--out 指定报告目录(默认在被评项目之外)
python3 <包根>/score_session.py <被评项目路径> --out <报告目录>

# 等价显式写法;--project-scan 只做拾取干跑(预览 + 确认,不出分)
python3 <包根>/score_session.py --project <被评项目路径>
```

**流程只有两次交互,中间全自动**:①开评前**预览确认一次** —— 评估先展示拾取
预览(形态判定 / ① 7 类命中 / ② 未识别清单 / ③ 排除统计 / ⑥ 文档簇清单 +
问题清单),在命令内
交互确认(回车/继续 = 开评;可拖入 / 剔除 / 改判,簇分得不对可并簇 / 拆出 /
拖入簇),**未确认不开评**;②交付时**问一次上云** —— 报告四件套落盘即交付,
要不要上云换链接,等评估完成后询问用户、同意才上(见下文「上云与仅本地」)。
两次交互之间(拾取 → 检查 → 评审包导出 → 就地评 → 灌回折算 → 渲染)全程自动,
不再有任何二次确认。非交互场景(CI/脚本)加 `--yes` 显式跳过①;簇的人工结论可用
`--cluster-map FILE.json` 在预览生成前钉死(顶层单键 `"clusters"`,值为组列表,
每组为文档路径数组:≥2 条 = 并簇、1 条 = 拆出;成员必须在拾取集内),
与 `--yes` 组合即非交互映射,报告簇结构行会标注映射条数。评估器自身不代答确认 ——
由调用方(agent 或人)应答。`--yes` 运行时仍会打印簇预览(成员 + 依据,
不等待确认、按机器结论开评),报告留痕「簇预览已展示、未经人工确认」。

报告四件套落 `--out` 目录:`*.md` 本地完整报告、`*.html` 同内容 HTML5
渲染版、`*.envelope.json` 原始指标存档、`*.cloud.json` 脱敏投影。报告全中文、
章序固定:总览 → P1-P6 六维章 → 补充说明组;逐条证据可复核,分数可手算对账。

**整包深评(问题档语义轨)五步流程 —— 会话内就地评,零第三方 API**:
深评语义轨(六问题打档)**不在引擎里调任何模型端点**,改为导出评审包、
由调用方 agent **开 sub-agent 逐包判定**、再把判定灌回引擎折算:

1. `python3 <包根>/score_session.py --project <被评项目路径> --yes` —— 跑机器侧
   (结构扫 / 聚类 / 定点召回,全本地确定性);
2. `python3 <包根>/score_session.py --project <被评项目路径> --deep-eval-export <包目录> --yes`
   —— 落盘 `problems.json` + 每问题 `pack-<pid>.md`(问题 + 六档 anchors 原文 +
   真实投喂片段)+ `verdicts.template.json`,零联网;**召回包每包数万字,绝不
   读进主会话上下文**;
3. **必须开 sub-agent 逐包评**:每个 sub-agent 只读自己那一包 `pack-<pid>.md`,
   按包内 rubric 打档,产出 `{"band":"0..5"字符串,"reason":中文,"citations":[{path,line_start,line_end}]}` 形判定(citation 必须命中包内片段出处,band ≥ 1 必须带有效 citation);
4. 汇总判定为一份 JSON(结构与 `verdicts.template.json` 同形,`pack_fingerprint`
   原样带回;每问题 1 票即可,兼容 1–3 票折算,多数档 / 平票取低段);
5. `python3 <包根>/score_session.py --project <被评项目路径> --deep-eval-import <判定.json> --yes`
   —— 引擎先校 `pack_fingerprint`(树 / 参数变了会退出 2,提示重新 export),
   再复用既有折算 / 门 / 渲染全链出完整报告。

只跑第 1 步不导入判定时,报告会诚实记「语义轨未评」(缺者按「没评出结论」
剔除分母,评分走既有降级路径,exit 0)—— 不要把「未导入」当「未评出问题」。

**文档轨接手核验(整包评估完成后必做)**:整包收尾对全量文档语料跑**一次**
「AI 接手核验」—— 按 P1–P6 六轴(与整包报告同轴同词)判每轴 覆盖/薄弱/缺失,
出**单份小结**(逐轴证据 + 缺口验收句),**不逐篇打分、不出逐篇报告**;bug/
瑕疵类信息不进核验结论。核验查「有没有」,不查写得好不好;要质量判断走问题档
深评(上文五步)或单篇 doc-eval 语义轨(下文 `--judge-export`/`--judge-import`):

```bash
python3 <包根>/score_session.py --doc-handoff <被评项目路径> --out <报告目录>
```

用户显式点名评某一份文档时,才用单篇 doc-eval(`--doc-list` 列候选 → `--doc`
评分,下文);绝不静默替用户砍单或加单。核验小结**默认仅本地**,用户主动要求
上云、经其同意后再用包内自带桥(桥上送报告全文、无自动密钥拦截,上云前
自行确认;详见下文「上云与仅本地」):

```bash
python3 <包根>/upload_report.py <核验小结.md> --name <项目名·接手核验>
```

桥自动把同目录同名 `.html` 一并上送(链接页 ⑧ 整页新页打开渲染版,沙箱
语义由 CSP sandbox 响应头实现);整包报告的链接页 ⑧ 也随载荷携带
**HTML5 渲染版**(与 doc-eval 同标准,md 全文兜底)
—— agent / hook / skill 检查、缺口清单、问题档深评结论都在渲染版全文里。

## 文档轨 doc-eval(随包,2026-09-06 自 vibe-eval 并入)

评「一份/一套项目文档能否支撑下一个 AI 接手」,产出 DQ 总分 + 文档级接手
等级 L4–L0 + 缺口清单。五把验收尺(通用 / 需求碰头 / PRD / 开发文档 /
测试文档)随包分发,包根 `rulers/*.json` 即数据权威;报告盖尺名 + 版本
指纹戳,尺不同版本的报告不可静默比对。

```bash
# 先列候选再选:列当前项目目录(--doc-dir 可改)下所有 .md/.txt(编号+路径)
python3 <包根>/score_session.py --doc-list
# 对选定文档评分:缺省 = 结构轨(确定性结构自检,报告明示「未接语义轨」)
python3 <包根>/score_session.py --doc <文档.md> --out <报告目录>
# 语义轨两步(零联网):①出评审包 ②由你(执行评估的 coding agent)按包内
#   提示词就地评定,再把判定灌回出分(补 DQ4,总分不再封顶 69)
python3 <包根>/score_session.py --doc <文档.md> --judge-export <包目录>
python3 <包根>/score_session.py --doc <文档.md> --judge-import <判定.json> --out <报告目录>
# 按阶段验收(默认自动判型,拿不准回落通用;可显式指定)
python3 <包根>/score_session.py --doc <文档.md> --stage prd --out <报告目录>
# 显式只要结构轨(--offline;CI/回归复现,离线口径同缺省并在报告注明显式离线)
python3 <包根>/score_session.py --doc <文档.md> --offline --out <报告目录>
```

尺子管理(改/加尺不改引擎,下一次 `--doc` 即生效):

```bash
python3 <包根>/score_session.py --ruler-list                        # 列注册表
python3 <包根>/score_session.py --ruler-show prd                    # 查看单把
python3 <包根>/score_session.py --ruler-detect --doc <文档.md>       # 干跑判型
python3 <包根>/score_session.py --ruler-validate prd --doc <文档.md> # 覆盖预览
```

> doc-eval 语义轨已改「导出-灌回」(零联网):引擎机器侧照常,语义判定由
> 本地 coding agent 就地评 —— `--judge-export` 出评审包 → agent 按包内提示词
> 评定 → `--judge-import` 灌回出分;引擎零联网、零模型端点、零 API key、
> 不读任何模型配置环境变量。缺省或显式 `--offline`(未灌回)时:DQ4 记缺口、
> 接手等级记 U、结构分封顶 69,报告明示「未接语义轨,结构分不具承载力含义」。
> 评估器对被评文档同样只读。

## AI 补拾(coding agent 就地补拾)

规则没认出来的文档,不再交任何模型服务商远程补分类(端点方案已整条退役,
引擎不读任何模型配置环境变量):补拾由**执行本次评估的 coding agent 自己
就地完成** —— 看「未识别文档清单」里每个文件,对照 7 类拾取规则自行判断
该归哪类:

- **无端点、无环境变量、零出网**:补拾就是你(会话内 agent)自己的判断,
  不读任何 `.env`,也不向任何服务发送路径或内容;
- 判断结果经**预览确认闸落地**:该收的用「拖入 <类>」改判动词在预览里钉死,
  拿不准的如实留在外;预览里剔除即否决;
- 预览确认闸不变:未确认不开评;你不参与补拾时,规则拾取照常,未识别清单
  原样摊开,报告如实记「未识别」。

## 上云与仅本地

**默认仅本地:不上云、零出网**,本地四件套即全部交付(2026-09-12 起)——
评估完成后 agent **询问用户**是否上云,**用户同意才执行**:整包轨加
`--upload` 重跑,文档轨跑包内 `upload_report.py` 桥;用户没点头绝不擅自上送。

**出网只有一类**,除此之外评估全程零出网:

1. **报告上云**(仅用户同意后的 opt-in;安全承诺按上云面分别如实,见下)。

语义判定全部就地完成,不向任何模型服务商发送项目内容:问题档深评 =
会话内 sub-agent 逐包评,文档轨接手评估 = `--judge-export` 出包 → coding
agent 就地评 → `--judge-import` 灌回,补拾 = coding agent 就地判断 ——
评估器引擎零联网、零模型端点、零 API key。

**整包轨上云(`--upload`,引擎构造载荷)—— 安全承诺四要点全量**:

- 只上传**最终报告与脱敏统计**(结构化分数、门、覆盖率、缺口结论、按类
  聚合),不上传任何源代码、原始数据、原始转录 —— 被评项目文件一个字节
  都不出网;
- 密钥只报「命中 N 处」,独立判据表复扫兜底,**命中即拒传、零原文**;
- 上云载荷带本地报告全文(HTML5 渲染版 + md;链接页 ⑧ 整页新页打开渲染版,
  沙箱语义由 `Content-Security-Policy: sandbox` 等响应头实现;含路径与证据结论);
- **链接只绑认领账号**:打开链接时已登录(非 admin)→ 自动绑定该账号,直出
  全文;未登录 → 登录后重开链接即绑定。一链接只绑一账号,别人打不开;
- 上云走 **http 明文传输,未加密** —— 不声称加密或安全传输。

**桥上云(`upload_report.py`,会话评分 / 文档轨)—— 与整包轨不同,桥不做
自动密钥拦截**:

- 桥上送**最终报告全文(.md,自动附同目录同名 .html)**,无自动密钥拦截
  —— 上云前请自行确认报告不含密钥原文;
- **链接只绑认领账号**(同整包轨);上云走 **http 明文传输,未加密**。

**仅本地开关**:敏感项目保持缺省即不上云;`--local-only`(或环境变量
`VIBE_EVAL_UPLOAD=off/0/local`,可否决 `--upload`)显式钉死不上云、零出网,
本地四件套即全部交付。

## 版本

```bash
python3 <包根>/score_session.py --version   # 一条命令:发布 / 引擎 / 规则 / schema
```

三轴并行、各管各的:**发布**(zip 名 / manifest / 报告戳跟它,每次对外交付递增)· **规则**(`rules_version`,评分口径,golden 锁绑它,不同规则版本的报告不可静默比对)· **引擎**(`_ENGINE_VERSION`,打包/信封轴,惯例长期不动)。发布历史随包 `CHANGELOG.md`;同名 zip 内容有差异会被打包闸拒绝(防「同一发布号两种内容」)。

## 报告怎么读

| 看什么 | 含义 |
|---|---|
| 总分 0–100 | 六维加权(报告 ② 节自带逐项判据表与评分口径,每项检查打到哪档、得多少分逐行可对账);三项硬性问题(密钥泄露 / 缺少可运行的验证 / 缺少持续集成)任一命中会封顶并在报告注明 |
| 项目形态 | service / cli / library / content / default:形态决定哪些检查适用(预览确认闸可改判);形态不同分数不可横比 |
| 接手等级 P4–P0 | 项目级接手等级,P4 = 这台尺子能机器证明的都证明了(与文档级 L4–L0 是两套记号) |
| 证据阶梯 | 每项检查:存在 = 60、互核 = 80、写实 = 100;敏感文件名检查最多记 60(扫描扫不出 ≠ 没有密钥) |
| 缺口清单 | 未满档检查项逐条:现状 + 验收句(重评自动复判)+ A 级预估提分;深评联动缺口才带 P0–P2 分级 |
| 临时结论 | 有「该查没查到」的证据(如深评离线回退)时如实标注,非完整结论 |

评分口径以仓库 `docs/evaluation-system.md` 为唯一真源(第三部分 = 工程设施轨:
六维 / 20 项检查 / 证据阶梯 / 项目形态 / 硬性问题 / P4–P0);本 skill 不解释
分数争议,引导看报告内复核线索。
