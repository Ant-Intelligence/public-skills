成本与 Token 治理

同样的活花更少的 token——养缓存、按难度分流模型、精炼上下文。对应 B9 / C3 两个域。
B9 资源效率C3 Token ROI 与成本治理
核心一句话：省 token 不是抠门，是让反馈更快、让好钢用在刀刃上。 同一件事，会治理的人花的成本可以差一个量级——而这套评分的 C3 域，奖励的恰恰就是这几件事。

两个真实杠杆：养缓存、分流模型

企业普遍设了 token 上限，冗长空转、反复倒大文件、什么活都用最强模型，都是真金白银地烧。更隐蔽的是：token 烋越多，每轮反馈越慢，你自己等得也累。成本治理好，省钱只是一半，另一半是反馈变快。

能撬动成本的，主要是两件 Claude Code 特有的事：养缓存（让前缀稳定命中、不反复重读）和按难度分流模型（轻活用快模型、硬骨头才上强模型）。下面分别给可抄的做法。

✗ 大而无当 把 docs/ 或 src/ 整目录 @ 进上下文、或把单个几百行的文件全文反复贴进 prompt，缓存全失效；改个错别字也默认最强模型烧着。
✓ 精炼 + 分流 只给相关片段、同上下文推进养缓存；轻活（改格式、写样板）切快模型，硬骨头才上强模型；长会话及时 /compact。

养缓存：让前缀稳定命中（C3 / B9）

Claude Code 有 prompt 缓存：上下文前缀稳定，后续回合就能命中缓存、不必重读，token 和延迟一起降。想让命中率高，记住一条——前缀别动。

  • 同一条任务主线持续推进，CLAUDE.md / 系统提示不要中途反复改，前缀稳定才能命中。
  • 别每轮重贴大文件：同一个文件读一次、后续引用即可，反复整篇倒进去等于反复把缓存清零重读。
  • 换任务才 /clear：清空历史（缓存归零）；同任务只是历史太长失焦，用 /compact——它把长对话压缩成摘要保留"软前缀"，比 /clear 省。
# /clear vs /compact —— 别用混
换任务了、旧上下文是包袱      → /clear   （清空，缓存归零）
同任务但历史太长、开始失焦    → /compact （压缩保留，软续接，更省）
每轮都 /clear = 反复把养好的缓存清零重读，最费 token

评分上看，这直接动两块：缓存命中率是内部 D1 的主轴（0.6·cache + 0.4·output），而 D1 又喂进 C3；C3 里"是否压缩"那一项，/compact 过就得满分、从没压过只有 40。所以——养缓存 + 及时 /compact，每一件都直接抬你的 C3。

按难度分流模型（C3）

这是省 token 最直接的杠杆，也是 Claude Code 特有的：不必什么活都用最强模型。轻活（改格式、写样板、批量重命名）用快模型，复杂推理、架构决策才上强模型。

三种分流手段，从粗到细：

  • 会话中途 /model：交互式切换，不丢上下文。重活切 Opus，琐碎读写切 Haiku。
  • 给子代理定档：在 agent 文件的 frontmatter 写 model:，让"这个角色"固定用一个档。比如 Claude Code 自带的 agent 里 architect / planner 写 model: opus（要深思），tdd-guide / code-reviewer 写 model: sonnet（执行类）。
  • 按任务挑不同档的子代理：轻活派给配 model: haiku 的执行型 agent，硬骨头派给配 model: opus 的深思型 agent——同一任务里按子任务难度选不同档，而不是从头到尾一个模型。

给一个机械重构 agent 定快档的最小写法：

---
name: refactor-helper
description: 机械重构 / 改格式 / 批量重命名
model: haiku          # 琐碎活用快模型，省 token
tools: [Read, Edit, Grep]
---

反直觉但重要：C3 的"模型分流经济性"那一项，用了 ≥2 档模型拿满 90 分，只用一档强模型（全 opus/sonnet）只有 45、只用一档弱模型（haiku）也只有 55。评分明确鼓励你按难度分流——不是越省越好，是花得合理。

精炼上下文、大请求拆增量（B9）

除了缓存和分流，还有一条朴素但有效：别倒整库。读大文件用 Read 的 offset/limit 只取相关段，而不是 @ 整个文件；先用 Grep 缩范围、再定向读命中的几行；别把 docs/ 或 src/ 整目录塞进上下文——只挂当前任务真正需要的。B9 量的就是计费 token / 回合（每个 assistant 回合烧多少），同样的产出花更少 token、B9 就高。

成本自检
  • ☐ 是不是在无谓地每轮重贴大文件？（动手：grep 一下 ~/.claude/projects/<hash>/*.jsonl，看同一文件内容是否在多条 user 消息里整段重复）
  • ☐ 同任务长会话，该 /compact 了吗？（别等到失焦才动）
  • ☐ 轻活有没有切快模型？（动手：/model 或给执行类 agent 写 model: haiku/sonnet）
  • ☐ 用了 ≥2 档模型吗？（C3 经济性项：只用一档强模型只有 45 分；单档弱模型 55；≥2 档才 90）
  • ☐ 单个 prompt 是不是一次要求改 >5 个不相关文件？（动手：拆成多个子代理并行，或 /clear 换主线后分批推进）
