安全、权限与供应链

别把密钥喂进对话、别跑危险命令；引入依赖要锁版本、审来源——对应 B5 / B6 两个域。
B5 安全/权限/合规B6 依赖与供应链
核心一句话：安全是高权重项，踩中了真疼。 在这套评分里，安全问题通过 B5 这个高权重域按权重拉低你的 L2 和总分——不是一句话封顶 60，但一条密钥泄露、一条危险命令，就够把本来 A 的会话拽到 C。把密钥、危险命令、不可信依赖挡在门外——这三类出事代价最大、又最容易事前拦住，花不了几分钟，却省掉后面大半的烂摊子。

先认清这三类：密钥、危险命令、不可信依赖

把密钥/token 粘进对话或提交进仓库，等于公开泄露；rm -rf 打到系统路径、curl | sh 执行远程脚本，一条命令可能毁掉环境；引入未审计依赖，则把供应链风险带进项目。这三类出事代价极大，事前拦住却几乎不花成本。

✗ 把密钥喂进对话 "这是我的 API key sk-...，你帮我调下接口。"——密钥进了对话历史，等于泄露。
✓ 用环境变量 + 审命令 密钥放 .env / 环境变量，代码里 os.environ 读取；危险命令先 echo 预演（rm -rf dist/ 安全，rm -rf ~/* 要命）；新依赖 npm view <pkg> time.modified 看维护、npm audit 过一遍；版本锁死、提交 lockfile。

密钥永不进对话、前端、仓库（B5）

密钥只该待在一个地方：环境变量。代码里用 os.environ.get(...) 读，.env 加进 .gitignore，提交前扫一眼有没有误带。最小骨架（零依赖，不用 python-dotenv）：

# .env（这个文件必须进 .gitignore）
LLM_JUDGE_API_KEY=sk-xxx
DATABASE_URL=postgresql://...

# .gitignore
.env
.env.*
!.env.example

# config.py —— 启动时读 .env，缺密钥直接报错
import os
API_KEY = os.environ.get("LLM_JUDGE_API_KEY")
if not API_KEY:
    raise SystemExit("LLM_JUDGE_API_KEY missing: 设到 .env(gitignored) 或环境变量")

更高一档：配 hook 自动拦（PreToolUse）

口头说"别放密钥"会忘，代码评审也总会漏。配一个 PreToolUse hook——在 Claude Code 真的执行 Write/Edit 之前扫一遍内容，命中密钥特征就直接挡住，根本写不进盘。等于把"别放密钥"从一条规矩，变成一道绕不过的机制。

hook 脚本（放 .claude/hooks/block_secrets.py）：

import sys, json, re
ti = json.load(sys.stdin).get("tool_input", {})
# 关键坑：Edit 没有 content 字段，文本在 new_string（必扫）/ old_string；只有 Write 才有 content
text = " ".join(filter(None, [ti.get("content"), ti.get("new_string"), ti.get("old_string")]))
SECRET = [r"sk-[A-Za-z0-9]{20,}", r"AKIA[0-9A-Z]{16}", r"gh[pousr]_[A-Za-z0-9]{36,}",
          r"-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----", r"AIza[0-9A-Za-z_-]{35}"]
for p in SECRET:
    if re.search(p, text):
        sys.stderr.write(f"Blocked secret write: {p}")
        sys.exit(2)      # PreToolUse 的 exit 2 = 阻断，这次写根本不执行
sys.exit(0)

注册到 .claude/settings.json：

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Write|Edit",
        "hooks": [{ "type": "command",
                    "command": "python ${CLAUDE_PROJECT_DIR}/.claude/hooks/block_secrets.py" }] }
    ]
  }
}

拦危险命令同理：matcher 换 Bash、读 tool_input.command、正则换成 rm\s+-[a-z]*r[a-z]*f\s+(/|~|\*)、DROP\s+TABLE、git\s+push.*--force 这类，命中即 sys.exit(2)。

一个区别别搞混：PreToolUse 的 exit 2 是阻断（工具调用根本不执行——安全拦截用这个）；PostToolUse 的 exit 2 是回喂（工具已经执行了，把结果喂回给 Claude 让它修——自动测试用这个）。安全要"事前拦"，所以用 PreToolUse。

这动的是哪个分：B5 直接进你的 L2 能力分——基线 55，每条密钥泄露扣 60、每条危险命令或红线删除扣 50，重踩直接归零。注意是按权重拉低，不再一句话封顶总分。

依赖锁版本、审来源（B6）

每引入一个第三方包，就等于把一段别人写的代码请进了你的项目。用之前花一分钟查三样：npm view <pkg> time.modified 看最近维护（半年没动就警惕）、下载量周下载 < 1000 或 npms.io 分 < 0.5 先别用、npm audit / pip-audit -r requirements.txt 零 High/Critical 才放进项目。

# 锁版本（提交 lockfile，别放开范围）
npm ci              # 严格按 package-lock.json 装，失配即报错（区别于 npm install）
pnpm audit          # 扫已知漏洞；--fix 只改 lockfile 不改 manifest
pip-audit           # Python：扫当前环境或 -r requirements.txt；-f json 给 CI 用
pip install --require-hashes -r requirements.txt   # 旧式哈希锁

尤其警惕仿冒名（typosquatting）：正经包叫 requests，仿冒的叫 request、reqeusts，手一滑就装错。版本要锁死——否则哪天上游推个带 bug 的新版，你的线上莫名其妙就挂了。

这动的是哪个分：B6 当前不打分。命中安装命令与否只改报告里的发现文案，真实的供应链卫生需要 manifest/lockfile/audit，转录里看不到足够信号——系统诚实标数据不足，不靠规则假装。所以这里的 npm audit / pip-audit 得你自己跑、在 CI 里卡住。

谨慎用 bypassPermissions

"教练模式/免确认"方便，但意味着放开了闸门：Claude Code 的每次 Edit/Write/bash 都不再问你一声，文件被覆盖、命令被执行、全程不打断。

比一刀切开 bypassPermissions 更稳的做法，是按需放行具体命令、禁掉敏感路径——在 .claude/settings.json 里：

{
  "permissions": {
    "allow": ["Bash(npm test:*)", "Bash(git status)"],
    "deny":  ["Edit(.env*)", "Read(./secrets/**)", "Bash(rm -rf *)"]
  }
}

常用命令放 allow 免确认，敏感文件和危险命令进 deny 永远拦——既省确认又留住护栏。必须开 bypassPermissions，就限定在子目录的 project-level settings（别用 user-level 全局开），开之前先 git status 确认工作区干净。（评分里 bypassPermissions 仅信息、不扣分，但风险实打实。）

安全自检
  • ☐ 对话/代码/提交里有没有明文密钥？（动手：grep sk-\|AKIA\|PRIVATE KEY）
  • ☐ 有没有配 PreToolUse hook，让密钥/危险命令写不进、跑不了？（B5）
  • ☐ 破坏性命令的目标路径看清了吗？（动手：先 echo <cmd> 预演或加 dry-run，确认路径不含 ~ / / / * / 未展开变量）
  • ☐ 新依赖审过来源、锁过版本、跑过 audit 吗？（B6）
  • ☐ 我清楚本次放开/禁了哪些权限吗？（动手：翻 .claude/settings.json 的 permissions.allow / deny）
