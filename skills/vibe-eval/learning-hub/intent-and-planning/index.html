意图表达与前置规划

把需求说清楚、把任务拆开、动手前先规划——让 Claude Code 少猜、少返工。
A1 意图表达与任务结构化 B1 需求澄清与前置规划
核心一句话：你把意图说多清楚，它就做多好。 与其丢一句模糊的话让它猜、再来回纠偏，不如前置几分钟把「要什么、不要什么、分几步」讲明白。

1. 为什么这项重要

AI coding 里最贵的浪费，不是模型不够聪明，而是需求没说清导致的反复返工：你以为它懂了，它按自己的理解写了一大片，结果方向不对，推倒重来。

2. 反面 vs 正面

✗ 模糊丢活 「帮我把这个页面优化一下。」——没说优化什么、约束是什么、改哪些文件不能动哪些，模型只能猜。
✓ 结构化表达 「重构 docs/report.html：① 左侧加固定目录导航；② 配色从紫色换成深蓝(更严肃)；③ 每条建议加可点课程链接。不要动打分逻辑。改完起本地服务截图给我看效果。」——目标、约束、验收方式都在。

3. 照抄:需求澄清骨架

把需求讲清不需要文采,照这五个槽填一遍,意图就结构化了——直接粘进对话,按提示改:

# 需求澄清骨架(粘进对话,按提示填)
目标:要做成什么?写成可验收的结果(不是"优化一下",而是"左侧加固定目录")
约束:哪些文件 / 逻辑不能动?不能引入什么依赖?
不要做:负向需求——往往比目标更防跑偏("不动打分逻辑"、"只动前端")
验收:做完怎么算对了?给能跑的命令 / 可见的界面 / 通过的测试
分步:拆成 3-6 步,每步一个可验收的小交付

让 Claude Code 用 TodoWrite / TaskCreate 落地时,每步带上验收标准,模型才不会「写完就算」。下面是它写进 todo list 的样子:

✗ 一句话丢活 「优化登录页」——模型只能猜优化什么、改到哪算完。
✓ 带验收的步骤清单 ① 重构导航 —— 验收:目录固定、不随页面滚动
② 配色 紫→深蓝 —— 验收:全站 grep 不到紫色残留
③ 加课程链接 —— 验收:点开能跳转
④ 不动打分逻辑(约束)

4. 四个可直接照做的动作

① 动手前先拆任务

让 Claude Code 先用 TodoWrite / TaskCreate 把活拆成明确步骤，你过一眼再让它动手。

你：先别写代码。用 TodoWrite 把这个需求拆成 3-6 个步骤，
    每步说清「改哪个文件、验收标准」，我确认后再动手。

评分器数的 plan_calls 不止 TodoWrite——TaskCreate / TaskUpdate / TaskList / ExitPlanMode 都算规划工具。建计划、随进度标完成、退出 plan mode,每一次都进 A1 / B1。

② 在关键节点用 AskUserQuestion 确认边界

岔路口让它先问你、别替你拍板。直接给它一句触发:

遇到岔路口先用 AskUserQuestion 列选项问我,别替我拍板:
① 状态库:Zustand 还是 Jotai?
② 数据模型:字段加列,还是单独建表?
③ 错误反馈:toast 还是 inline?
列选项、等我选再动。

③ 先给「不要做什么」

骨架里的「不要做」槽别空着,具体到文件 / 依赖 / 范围:「不要改数据库 schema」「不要引新依赖」「只动前端」。

④ 用 Plan / 设计先行的工作流

较大的改动，先让它产出一份简短设计(改动点 + 影响面 + 验收方式)，你批准后再实现。进 plan mode 让它只规划不动手,或调 brainstorming skill 先发散对齐再收敛。

B1 · 动手前，把需求和计划定下来

前面四条偏 A1——「把一句话说清楚」。B1 更进一步，是动手之前的事：比如把「优化一下登录」澄清成「加 remember-me 复选框、token 自动刷新、连续失败三次弹验证码」——每条都能单独验收，顺序一目了然。

这动的是哪个分：拆任务 + 确认边界，直接抬你的 A1（L1 意图结构化）和 B1（L2 前置规划）——两个域的主信号都是 plan_calls（规划工具次数）。关键在 k 很大：A1 的 struct 子分 100·n/(n+90)、B1 是 30 + 0.55·struct(k=40)（有封顶——有规划只是入场、不等于规划质量）。开头列一次 TodoWrite 和边做边更新十几次，得分差一个量级：struct 在 n=1 时 ≈1、n=10 时 ≈10、n=90 才到 50；B1 在 n=1 时 ≈31、n=40 时 ≈58。所以要贯穿会话——建计划、每完成一步 TaskUpdate 标完成、关键节点重新整理——不是开头列一次就完。AskUserQuestion 确认点抬 A1 的 confirm 子分（k=180，同理要持续问）。正文可解析时 A1 还叠 30% 的 prompt_score（按平均提示长度衡量的具体度代理）；压缩转录下提示长度是死信号，这时结构化工具证据才是 A1 的全部——即便转录被截断，你拆了任务、问了边界，A1 照样有分。

动手前自检清单
  • ☐ 目标说清了吗？（要达成什么可验收的结果）
  • ☐ 约束说清了吗？（哪些不能动、不能引入什么）
  • ☐ 拆成明确步骤了吗？（而不是一句话丢活）
  • ☐ 每步的验收标准说清了吗？（怎么算这步做完，对应 B1）
  • ☐ 岔路口让它先问、而不是替我猜了吗？
  • ☐ 大改动先要了一份计划/设计吗？
